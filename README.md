# 手机联网与小说工坊

当前版本：1.4.0。新增固定版本检查/在线更新入口和更新通知；小说建档采用概括型完整世界书，目标1万—2万字：关键事件、主要人物性格与轨迹、重要关系、核心世界观和整体文风。按全书规模分配逐章概括长度。取消逐字引文匹配要求；无效条目略过，整章失败也继续后续章节，连续失败不自动暂停。

这是本地SillyTavern纯前端扩展，使用酒馆自带网页接口和你配置的模型，不需要额外服务器插件，不依赖电脑Edge。兼容测试基线为SillyTavern 1.19.0；未做安卓实机测试。

## 安装与更新

在酒馆“扩展 → 安装扩展”中填写仓库地址：

```text
https://github.com/knowledgeeee/sillytavern-mobile-web-novel
```

已安装用户在管理扩展中更新原扩展，再刷新页面，不要重复安装。配套角色卡可选，无需更换现有角色。ZIP可从GitHub Releases下载，用于本地复制安装；网址安装应填Git仓库地址而不是ZIP地址。

## 更新入口与首次手动更新

1.4.0起，“手机联网”面板顶部固定显示当前运行版本、“检查更新”“在线更新”和发布页链接，不依赖宿主管理器临时显示下载图标。默认前台每6小时检查一次，发现新版本会提醒；本入口不会自动安装，更新由你点击，完成后明确提示刷新。小说建档期间拒绝拉取更新，避免打断任务。

Git安装且宿主支持原生更新接口时，可直接在线更新；ZIP/解压安装没有Git记录，面板会说明不能在线拉取，并给出发布包链接。不会卸载重装、清空书库、重置Git或生成第二份扩展。接口不支持/网络失败时也不会误报“已是最新”。

清单已启用酒馆标准`auto_update`标记，宿主更新通知还取决于宿主的通知选项；宿主自身的自动更新行为仍按宿主设置运行。扩展内的自动检查可独立关闭。

旧版本没有新入口，必须先手动更新一次。Termux用户可先等待当前读取任务完成，再运行下面的命令；它只查找这两个扩展目录名，确认目录自身有Git记录后才执行快进拉取，不会退到酒馆主仓库更新：

```sh
find "$HOME" -type d \
  \( -name 'sillytavern-mobile-web-novel' -o -name 'mobile-web-novel' \) \
  -path '*/extensions/*' -prune \
  -exec sh -c 'if [ -e "$1/.git" ]; then git -C "$1" pull --ff-only; else echo "此扩展没有 Git 记录：$1"; fi' sh {} \;
```

完成后刷新手机酒馆页面。如果命令没有任何输出，说明安装路径不在Termux HOME内或目录名称不同，需要根据启动脚本确认路径。若提示没有Git记录，使用发布ZIP覆盖现有扩展目录，不能靠此命令更新；不要直接卸载或新建另一份。

本地安装时，把`mobile-web-novel`文件夹放进酒馆`data/default-user/extensions/`，确保manifest.json位于文件夹第一层。多用户替换为实际用户目录；封装应用是否支持ZIP导入取决于其功能。

## 阅读与精简世界书

1. 打开任意单人聊天，点“手机联网”，填写公开小说目录或单章网址。
2. 可先点“预览/刷新目录”和“测试前2章正文”，确认章数与网页读取；这两项不调用模型。
3. 点“读取/继续建档”，默认累计读取到第6章，也可调整章节数或读取全书。会自动为当前聊天启用小说模式。
4. 点“查看世界书”查看精简概括；“查看章节概括/异常”查看每章结果和未纳入原因。
5. 设置第一/第三人称、代入角色、自定义场景，生成场景菜单或在聊天中继续。

新建档不保存原文引句，不要求evidence字段。每6000字符材料通常调用模型提取和校核各一次。系统按完整篇幅目标、目录章节数与当前正文长度分配概括密度；例如26章目录会给每章保留更充分的信息，1000章长篇则精炼每章，不是所有书每章都压成几百字。重点是改变后续走向的事件、人物目标/性格与重要经历、关系变化及持续后果、关键规则、秘密和文风。语义以模型校核为主，本地检查结构；不是事实正确性的保证。

完整世界书按全书规模组织，目标1万—2万字，默认约1.5万字。在“完整世界书目标篇幅”选择1万、1.5万或2万，点“应用建档设置”后用于查看及导出。字数按正文字符估算，不含JSON字段；短书、未读完或资料不足时不硬凑字数，不编造内容。

完整视图最多16位主要人物，每人保留性格/目标和多个重要经历节点；事件大纲、人物关系、核心世界规则、时间顺序、未解线索与文风分区组织。人物、事件等分类共享整体篇幅，某类资料较少时把剩余容量分给其他分类，避免小人物表导致整本世界书被压成几百字。底层章节概括不等于完整世界书篇幅；模型和自动筛选仍可能漏掉重要细节，不追求逐个动作和全部配角流水账。

聊天按当前角色和场景，从完整世界书中选取较小的相关资料包，不会每轮注入整份一两万字内容。标准世界书导出使用完整视图；两者不要混淆。

亲密关系可用非露骨文字概括伴侣关系、信任、权力关系、同意与边界、关系转折及持续剧情后果。文风提炼抽象叙事特征，不建立色情词汇库或记录性行为过程。

旧版详细档案仍留在书库备份中，但查看和导出会自动精简，不必重读原文或重新花模型用量。已有成功章节不会重复建档。当前“导出故事档案”是逐章数据备份，可能大于精简世界书，且尚不支持一键导回扩展。

如果旧的逐章概括本身过短、无法支持一两万字完整内容，可以点“按当前篇幅重建已有概括”。这会重新读取并概括当前累计章节范围，产生额外模型用量，成功才替换旧结果，失败保留旧概括并继续。网页原文已删时尝试重新下载；TXT可重新导入完全相同的原文件补回原文，不覆盖旧概括，再点重建。只调整篇幅不会凭空生成缺失资料。

## 失败时继续处理

- 格式错误的个别条目略过，其余有效概括照常保存。有条目被略过的章节会保留原文并显示异常。
- 整章输出为空、JSON无法修复或网页读取失败时，标记为未纳入概括，保留已缓存原文，然后继续下一章；连续失败不自动暂停，也不循环重试同一章。
- 世界书和续写明确标记缺失章节，不能把缺失剧情当作已读。某章失败不阻止使用其他成功章节。
- 点“重试待处理章节”可重试当前累计章节范围内的失败/部分异常项；成功章节复用缓存，不重复调用模型。普通“读取/继续建档”会重试整章失败项。
- 只有用户点击暂停、切换聊天，或者任务本身无法启动等情况才结束当前任务。发现接口不可用时可手动暂停，避免后续章节继续产生请求和用量；没有无限自动重试。

建档输出额度默认每次5000 token，可设2400—16000，仍受供应商上限约束。额外思考可能占用额度，空输出或JSON截断会导致该章被略过。此前DeepSeek配置可保留`thinking: { type: disabled }`对应的自定义请求参数；不要把此参数套到不支持它的其他接口。

## 原文保存、进度与导出

新书默认在章节概括成功、没有格式异常且数据库保存成功后删除对应原文。失败/未处理/部分异常章节保留已缓存原文。可勾选“建档后保留原文”并应用设置；读新书前应用也有效。开启保留不能恢复此前已经删除的原文。TXT请始终自行保留原文件备份。

更新不改变旧书已经保存的原文策略；没有明确策略的更早旧书默认保留。点击“清理已建档原文”只清理当前书已成功、无异常章节，其他书和异常章节不受影响。新式概括不保存引文；旧版备份中原有的引文不会自动删除。

“故事进度上限”用于避免把较后章节事实带入较早场景；留空使用最新可用章节。存在缺章时会明确标注未知，不伪称连续读完。

“导出酒馆世界书”生成标准JSON，可在酒馆世界书面板导入、编辑及绑定其他角色。条目带章节标注，书籍来源网址在元数据中记录一次，不在每条重复。扩展模式已提供同类资料，建议关闭小说模式后再绑定导出的世界书，避免重复注入。

书库保存在当前浏览器IndexedDB，按酒馆账号隔离；不是服务器世界书，也不自动同步电脑和手机。清除网站数据、换浏览器/端口或重装应用可能导致书库不可见或丢失。模式、人称、角色和所选书籍按聊天保存；群聊暂不支持。

## 续写校核

场景菜单生成后额外调用一次模型作一致性校核。普通回复可按需点击“校核上一条回复”，额外调用一次模型，检查伤势、人物所知、物品、时序、人称和擅自补写过去等问题；可点“撤销上次校核”恢复前文。模型仍可能漏查或误改，校核不是逻辑正确性的保证；不会自动为每轮普通聊天增加校核用量。

## 给任意角色联网

配置原有模型API后，点“启用工具（非流式）”。支持工具调用的聊天补全模型可使用`mobile_web_read`读取网页、`mobile_web_search`尝试Bing公开网页搜索。此按钮打开function calling、关闭流式输出，并把merge/semi/strict后处理切换为保留工具的对应模式，不改写模型名或API密钥。

每轮读取和搜索合计最多3次；网页读取每次提供最多6500字符，可用offset继续。搜索摘要不是读过正文；失败会返回明确警告。工具调用由模型决定，不能保证每轮都使用。小说分章建档不依赖工具调用，也不受这3次上限影响。

不支持工具调用时可填网址，点“读取上方网址交给模型”，再在当前聊天提问。网页文字是不可信资料，不执行其指令。网页受限可导入UTF-8 TXT；开始建档时正文会发给当前模型服务。

## 网络与兼容边界

调用手机本地酒馆服务器的`/api/search/visit`访问公开网站，解决的是浏览器跨域问题，不绕过登录、验证码、付费或反爬；不会继承手机浏览器对小说站的登录态。CSRF令牌失效会刷新重试一次，临时上游错误最多重试一次。正文分页间隔1秒，检测重复和循环，单章最多100页/20万字符。

保持页面前台。Android省电、锁屏或浏览器休眠仍可能冻结任务；扩展不能阻止操作系统暂停网页。404通常表示酒馆缺少接口，500可能是网络或目标站失败。目录跨页、交互展开或图片小说仍可能需要适配或TXT导入。

## 测试范围

1.4.0在电脑版酒馆交互页面验证更新入口、更新提示、ZIP与不支持接口分支、失败不误报，以及通过真实宿主Git接口拉取一次性旧版样本。此前还验证改写摘要不依赖逐字原文、无效条目略过、连续三章失败后第四章继续成功、手动重试复用成功缓存、部分异常保留原文、篇幅设置、TXT补回原文和重建，以及真实模型建档、人物轨迹、世界观、文风、导出、场景和续写。240章结构化合成档案验证约1.5万/2万字导出容量及按需聊天检索。测试使用非露骨合成样本，未做安卓实机验证。

此前1.2.0对用户提供的三个站点目录识别26、78、35章并读取各前两章分页；不代表读过整本，站点变化仍可能导致失败。新版本保留这些目录和分页修复。
